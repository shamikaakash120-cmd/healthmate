# HealthMate — Manual System Test Cases

This table defines 10 end-to-end manual acceptance test cases covering CRUD persistence, validation, filtering, sorting, CSV export, settings overrides, navigation safety, and responsiveness. Fill in **Actual Result** and **Status** (`Pass` / `Fail`) after testing on device or web.

> Automated pure-logic unit tests (`25` passing cases across `validateRecord`, `dateUtils`, `csv`, and `dashboardLogic`) also run via `npm test` (`__tests__/*.test.js`).

| Test ID | Scenario | Input | Expected Result | Actual Result | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| TC-01 | Initial launch & automatic sample seeding | Launch app on a fresh install / cleared storage with an empty `health_records` table | App boots past `"Preparing HealthMate..."`, creates tables (`health_records`, `settings`), seeds 11 entries across the last 10 days, and renders Dashboard totals, rings, streak, and 7-day chart. | | |
| TC-02 | Add new record with quick-add chips | Open Add Entry (`+`), keep today's date, tap `+2500` steps twice (`5000`), enter `240` calories, tap `+500` water (`500`), tap **Save Entry** | Success Snackbar `"Entry saved. Great work!"` appears; modal closes cleanly; Dashboard today totals, rings, and History list increment immediately. | | |
| TC-03 | Form validation rejects invalid / blank / future inputs | In Add Entry, leave Steps blank, enter `-10` or `12.5` in Calories, enter `25000` in Water, and attempt to pick tomorrow's date | Save is blocked; friendly inline error messages display beneath invalid fields; future date is blocked by picker / validator; no SQLite write occurs. | | |
| TC-04 | Edit an existing entry | On **History**, tap the Edit (pencil) icon on any record, update Steps to `9200`, tap **Update Entry** | Form prefills existing date/values cleanly; updated record saves via `UPDATE ... WHERE id = ?`, refreshes History and Dashboard totals, and shows confirmation Snackbar. | | |
| TC-05 | Delete record with confirmation & empty state handling | On **History**, tap Delete (trash) icon -> **Cancel**, then tap Delete -> **Delete** on all remaining entries | Cancel dismisses modal without deleting; confirming removes row from SQLite, shows `"Entry deleted."` Toast; when 0 records remain, History shows `"No entries yet. Tap + to log your first day."` empty state and Dashboard resets to zeros cleanly. | | |
| TC-06 | History single-date search & non-matching filter | Tap **Filter by date**, select a date with records, verify list, clear via chip `×`; then filter by a valid past date with 0 entries | Active chip (`Filtered: ...`) displays matching entries; tapping `×` restores full list; unmatched date displays `"No entries for this date"` with **Clear filter** CTA. | | |
| TC-07 | History date-range validation, sorting & CSV export | Open **Date range** and set `From > To` -> **Apply**; next apply a valid range, switch sort to **Most steps**, and tap **Export CSV** | Invalid range (`From > To`) shows `"From date must be on or before To date."`; valid range filters list + shows Range chip; list reorders descending by steps; CSV file (`id,date,steps,calories,water`) downloads (Web) or opens native Share sheet (Mobile). | | |
| TC-08 | Custom daily goals & theme persistence across app restart | In **Settings**, change Steps goal to `8000`, tap **Save Goals**, switch Appearance to **Dark**, force-close app, and reopen | Toast confirms save; Dashboard rings immediately recalculate against `8000`; Dark palette applies across all screens immediately; after cold restart, `8000` goal and Dark theme remain active from SQLite. | | |
| TC-09 | Web direct URL refresh & safe navigation fallback | On Web, open `http://localhost:8081/record-form` directly (or refresh page on `/record-form`), then tap Cancel or close (`×`) | Screen navigates back to `/` via `safeGoBack` (`router.replace('/')`) without throwing `"The action 'GO_BACK' was not handled by any navigator."`; double-tapping `+` opens only one modal (`safePush`). | | |
| TC-10 | Keyboard overlap, rotation & large font scaling | Focus bottom input (`Water (ml)`) on Add Entry / Settings; rotate device between portrait and landscape; enable larger system font size | Active input and Submit buttons stay reachable above the soft keyboard; landscape rotation keeps centered `maxWidth: 720` scroll layout and Delete modal buttons unclipped; chips and toolbars wrap cleanly without overlapping text. | | |
